## Why

Арендодатель пока не может самостоятельно добавить помещение в RoomHub: публичный каталог читает только заранее загруженные записи. Нужен защищенный MVP-сценарий, который позволит юридическому лицу с ролью `LANDLORD` опубликовать валидное объявление и сразу сделать его доступным арендаторам.

## What Changes

- Добавляется защищенный `POST /api/listings`, принимающий данные коммерческого помещения и возвращающий созданное опубликованное объявление с `201 Created`.
- Организация-владелец определяется исключительно по bearer access token; клиент не может назначить объявление другой организации.
- Публиковать объявления может только роль `LANDLORD`; неаутентифицированный запрос получает `401`, а пользователь с ролью `TENANT` — `403`.
- Входные данные проверяются до сохранения: обязательные текстовые поля не могут быть пустыми, почасовая цена и вместимость должны быть положительными, тип помещения должен входить в поддерживаемый enum.
- Созданная запись получает `PUBLISHED`, серверное время создания и `owner_organization_id`, после чего появляется в существующем `GET /api/listings`.
- Runtime и экспортируемый OpenAPI-контракт дополняются новой операцией, схемой запроса, bearer security и ответами ошибок. Существующий контракт `GET /api/listings` не меняется.
- Добавляется Flyway-миграция, закрепляющая обязательные текстовые поля, положительные цену и вместимость на уровне PostgreSQL.
- Минимальная длина пароля регистрации устанавливается в 8 символов и синхронизируется между validation, OpenAPI и спецификацией.

Пример запроса:

```http
POST /api/listings
Authorization: Bearer <landlord-access-token>
Content-Type: application/json

{
  "title": "Переговорная в центре",
  "description": "Экран, флипчарт и кофе-зона",
  "city": "Барнаул",
  "address": "проспект Ленина, 10",
  "pricePerHour": 2500.00,
  "capacity": 20,
  "spaceType": "MEETING_ROOM",
  "imageUrl": "https://example.com/listing-42.jpg"
}
```

Пример ответа `201 Created`:

```json
{
  "id": 42,
  "title": "Переговорная в центре",
  "city": "Барнаул",
  "pricePerHour": 2500.00,
  "capacity": 20,
```

## Capabilities

### New Capabilities
- `landlord-listing-publication`: защищенная публикация объявления арендодателем, валидация входных данных, привязка к организации и немедленное появление в публичном каталоге.

### Modified Capabilities
- `openapi-contract-publishing`: runtime и экспортируемый контракт должны документировать операцию публикации, ее request/response schemas, bearer security и ответы ошибок.

## Impact

- API: новый непубличный `POST /api/listings`; существующий `GET /api/listings` сохраняет текущий response schema, поэтому изменение обратно совместимо для frontend.
- Backend: расширяются listing controller/service/repository, добавляется request DTO и обработка ошибок доступа/поиска организации по JWT claims.
- Security: маршрут требует валидный bearer token и роль `LANDLORD`.
- Database: используется существующая таблица `listings`; новая миграция добавляет `NOT NULL`/`CHECK` constraints без новых таблиц или полей.
- OpenAPI: обновляются runtime-документация, contract tests и `openapi/roomhub-b2b.openapi.json` через существующий Maven export pipeline.
- Tests: покрываются успешная публикация, валидация, роли, аутентификация, владение и видимость созданной записи в публичном каталоге.
